# Cuidar ERP - Vila do Aprender

面向教育机构的桌面管理系统，采用离线优先（offline-first）架构。作为原生桌面应用构建：
后端使用基于 **Tauri 2** 框架的 **Rust**，前端使用 **TypeScript / React**，数据持久化于
**内置 SQLite** 数据库。该系统为巴西萨尔瓦多的一所幼儿园按需定制开发与交付。

> **作品集项目。** 本仓库是某商业项目的公开脱敏版本。凭据、内部文档、私钥与客户数据均已
> 移除。此处不包含任何可用于伪造许可证或恢复生产环境机密的信息。

## 项目背景

本项目由一所幼儿园委托开发，属于按需定制的专有软件。客户提出的约束条件对一套管理系统而言
并非常见：负责日常行政工作的人员没有技术背景，机构没有自己的 IT 基础设施，而软件不能
依赖任何可能在未来停止付费的外部服务。

因此，产品围绕四项不可妥协的要求进行设计：

1. 必须能够在单台 Windows 机器上完整运行，并在无网络环境下继续工作。
2. 不能占用有意义的硬件资源，因为它要与机构的日常事务共用办公设备。
3. 必须让非技术用户在无需培训的情况下操作。
4. 不得将学生、员工或财务数据暴露给任何第三方。

---

## 问题

通用的学校管理系统都假定机构拥有 IT 部门，而这所机构没有。可选的方案是：

- 采购云端 SaaS 产品。这会把儿童与员工的个人数据放到第三方服务器上，并为一个仅需记录
  出勤与学费的功能引入永久性的月度成本。
- 使用电子表格。它无法保证数据完整性，无法产出可靠报表，并且会丢失版本历史。
- 开发 Web 应用。它需要服务器、域名，以及对这些资源负责的人员。

这三种方案都在同一个维度上失效：它们都假定操作者具备技术能力，而实际操作者是一位教研
协调员。

---

## 解决方案

一款原生桌面应用，彻底取消服务器。没有需要部署的后端、没有需要续期的域名、也没有需要
创建的账户。程序启动后打开本地窗口，读取本地文件。

由此产生的设计取舍是明确的：

- **使用原生 Shell 而非浏览器。** Tauri 渲染 Web 前端，但将其运行在操作系统自带的
  WebView 中，因此在保留现代前端技术栈的同时，安装体积与常驻内存远低于 Electron 应用。
- **SQLite 编译进可执行文件。** 数据库引擎静态链接，因此没有数据库服务器、没有需要
  安装的服务，也不需要开放端口。
- **数据存放于安装目录之外。** 数据库保存在系统级的应用数据目录中，因此升级程序或卸载
  绝不会影响机构的业务记录。
- **分层的命令模型。** 所有数据访问均以类型化命令暴露，通过框架的 IPC 桥接调用。前端
  不存在直连数据库的路径。
- **内置本地服务器。** 该功能可选、默认关闭，且仅绑定本地网络接口，使应用可以在不向
  互联网暴露任何内容的前提下，被同一局域网内的手机或平板访问。

---

## 成果

这是一款单次安装的桌面应用，覆盖了该机构的全部行政流程：学生入园登记与学籍记录、
班级管理、出勤、月度学费催收、带角色访问控制的员工管理、事件记录、按学生计费
的附加服务、固定支出、收入与支出管理，以及可导出为 PDF 与 Excel 的报表套件。

由于全部数据集中存储于一个带自动备份的本地文件中，该机构不承担任何经常性基础设施成本，
没有外部数据处理，也不依赖第三方服务持续可用。

## 技术栈

### 语言与运行时分层

本应用并非单语言代码库。它由三个层次组成，各自拥有独立的工具链。

| 层次 | 语言 | 工具链 | 职责 |
| --- | --- | --- | --- |
| 桌面后端 | Rust 2021（MSRV 1.77） | Cargo | 全部业务逻辑、持久化、安全与 IPC |
| 用户界面 | TypeScript 5.4.5（strict） | Next.js 14 构建 | 所有页面与交互 |
| 原生工具 | Rust 2021 | Cargo | 安装程序、卸载程序与许可证库 |

**Rust 与 Tauri 的区别。** 二者并非可选项的关系。Tauri 是应用框架，Rust 是后端所使用
的语言。Tauri 本身是一个 Rust 框架，因此选择 Tauri 就意味着为后端选择 Rust。本项目中
Rust 被用于整个后端，而不仅仅是 Tauri 所要求的部分。

### 调用路径

所有数据访问都遵循同一条路径，没有例外：

1. 界面调用一个统一的调用辅助函数，负责序列化参数。
2. 在桌面构建中，请求通过框架的 IPC 桥接分发。
3. 在浏览器中，同一辅助函数回退为向本地服务器发送 `POST /rpc` 请求，附带会话 Token
   并转换参数命名约定。
4. 后端校验输入、执行权限检查、执行语句，并返回序列化结果。

在任何构建形态下，前端都不与数据库直连。

## 安全模型

| 控制项 | 实现方式 |
| --- | --- |
| 密码存储 | 使用库默认工作因子的 bcrypt。明文永不被持久化或写入日志 |
| 会话 Token | 使用 HS256 签名的 JWT。访问 Token 有效期 8 小时，刷新 Token 有效期 30 天 |
| 签名密钥 | 从 `JWT_SECRET` 环境变量读取。未设置时在进程启动时生成密码学随机值，因此源码中不存在固定密钥 |
| Token 存储 | 数据库中仅写入会话 Token 的 SHA-256 指纹 |
| 暴力破解防护 | 最多 5 次失败尝试，随后锁定 15 分钟，并记录于 `login_attempts` |
| 授权 | 基于角色。每个命令都在服务端强制执行自身的角色要求 |
| 审计轨迹 | 安全相关操作写入 `audit_log`，记录操作者与时间戳 |
| 许可证校验 | 由安装程序验证 Ed25519 签名。签名私钥不包含在本仓库中 |
| 输入校验 | 针对身份证件、邮箱地址、电话号码、日期与金额的集中校验模块 |
| 数据隔离 | 数据库存放在安装目录之外，升级与卸载不会破坏业务记录 |
| 网络暴露 | 可选的本地服务器仅绑定本地接口，并有意省略敏感的恢复类命令 |

## 从源码构建

### 前置条件

- Node.js 20 或更高版本
- Rust 工具链，稳定通道
- Microsoft C++ Build Tools（`rusqlite` 内嵌 SQLite 编译所需）
- WebView2 运行时（Windows 10 与 11 默认已安装）

### 安装依赖

```bash
npm install
```

### 开发模式

```bash
npx tauri dev
```

### 生产构建

```bash
npx tauri build
```

产物：`src-tauri/target/release/bundle/msi/`

### 环境变量

| 变量 | 用途 |
| --- | --- |
| `SENHA_PADRAO` | 初始管理员凭据。用于创建首个账号 |
| `JWT_SECRET` | Token 签名密钥。未设置时在启动时随机生成 |

本仓库不存储任何机密信息。变量名记录在 `.env.example` 中。

### 关于安装程序 crate 的说明

`instalador/` 与 `instalador-dll/` 这两个 crate 会在编译期内嵌
`dist/cuidarerp-latest.msi`，而 `dist/` 是不会提交的构建产物。要编译这两个 crate，需先
生成 MSI（执行 `npx tauri build`，或运行项目中的 `compilar_instalador.bat`），并将其放置
在 `dist/cuidarerp-latest.msi`。应用程序本身可直接从全新克隆构建，无需该步骤。
